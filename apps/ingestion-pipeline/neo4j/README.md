# Neo4j — Knowledge Graph Layer

Schema, configuration, upload, and validation for the MemoryTonic knowledge graph.

---

## Setup

### 1. Neo4j Desktop

1. Install [Neo4j Desktop](https://neo4j.com/download/)
2. Create a DBMS named `memorytonic`
3. Set a password
4. Start the DBMS
5. Click "Create database" and name it `memorytonic`

### 2. Credentials

Create `.env` in this directory (gitignored — never commit):

```env
NEO4J_HTTP=http://localhost:7474
NEO4J_USER=neo4j
NEO4J_PASSWORD=your-password-here
NEO4J_DATABASE=memorytonic
```

All scripts import from `config.py`, which reads these env vars. Supports `.env` file via `python-dotenv` (optional dependency). Falls back to OS environment variables if dotenv is not installed.

### 3. Bootstrap Schema

```bash
python neo4j/bootstrap.py            # Create schema (idempotent)
python neo4j/bootstrap.py --status   # Show database stats
python neo4j/bootstrap.py --clean    # DESTRUCTIVE: wipe all data + rebuild schema
```

## Node Properties

### Project

```
projectId       — UUID (unique)
name            — Human-readable display title (e.g., "The Petrodollar System")
uniqueId        — Kebab-case slug (e.g., "petrodollar-system")
summary         — 200+ word project summary
narrativeFlow   — String array of ordered key moments
domain          — Tag domain
subdomain       — Tag subdomain
baseTags        — String array of tags
htmlPath        — Path to formatted HTML (e.g., "data/sources/2026-04-05/project/01_html.html")
directory       — Directory name
embedding       — 384d float array (BERT, cosine similarity)
createdAt       — DateTime
```

### Entity

```
entityId              — UUID (unique)
name                  — Entity name
aliases               — String array of alternative names
aliases_text          — Comma-joined aliases (for fulltext search)
category              — One of 14 categories (see below)
definition            — 100+ chars, system mechanics
role                  — Stance + mechanics + reasoning
firstAppearanceIndex  — Links to temporal phase
projectCount          — Number of projects this entity appears in (bridge detection)
embedding             — 384d float array (BERT, cosine similarity)
createdAt             — DateTime
```

**14 Entity Categories:** Person, Organization, Place, Event, Concept, System, Process, Technology, Law, Agreement, Metric, Document, Resource, Other

### TemporalEvent

```
eventId     — UUID (unique)
projectId   — Parent project ID

period      — Time period string
```

### CausalChain

```
chainId      — UUID (unique)
name         — Chain name
description  — What this chain traces
linkCount    — Number of links
projectId    — Parent project ID
createdAt    — DateTime
```

### Collection

```
collectionId  — UUID (unique)
name          — Collection name

```

### DateTime

```
datetimeId  — Date string or timestamp (unique)
```

## Upload Process (upload.py)

Batched HTTP operations — typically ~7 HTTP calls total regardless of entity/relationship count.

```
Step 1-3: Scaffold (DateTime + Collection + Project + structural links)  ~3 calls
Step 4:   Entity nodes (check existing + create/merge + MENTIONED_IN)    3 calls
Step 5:   TemporalEvent nodes                                           1 call
Step 6:   RELATES_TO relationships                                      1 call
Step 7:   FIRST_APPEARS_IN links                                        1 call
Step 8:   CausalChain nodes + CHAIN_LINK relationships                  2 calls
Step 9:   Embeddings stored as node properties                          1 call
```

**Bridge entity detection:** When creating entities, `upload.py` checks if the entity name or any alias matches an existing entity. If matched, it increments `projectCount` instead of creating a duplicate.

## Validation (validate_project.py)

Lifecycle gate — runs BEFORE upload, blocks malformed data from entering Neo4j.

```bash
python neo4j/validate_project.py --human <project-dir>   # Readable output
python neo4j/validate_project.py <project-dir>            # JSON output (for automation)
python neo4j/validate_project.py --all data/extracted     # Batch validate all projects
```

### What it checks (30+ rules)

- **File presence:** All 6 artifacts exist
- **02_placement.json:** 5 required fields, correct names, types, ID consistency
- **04_all_entities.json:** Temporal phases, entity fields, 14 valid categories, 100+ char definitions, no duplicates
- **06_extraction.json:** `project` wrapper present, top-level keys exactly `{project, relationships, causal_chains}`, summary 200+ words, narrative_flow as strings, 9 required relationship fields, entity name cross-references, 15 valid causal classifications
- **05_embeddings.json:** `embeddings` array format (not split entity/project), 384 dimensions, count = entities + 1, entity name matches
- **Cross-file:** unique_id consistency across placement/extraction, entity name alignment across entities/extraction/embeddings

### Exit codes

| Code | Meaning |
|------|---------|
| 0 | PASS (may have warnings) |
| 1 | ERRORS found (must fix before upload) |

## Common Cypher Queries

```cypher
-- Database overview
MATCH (n) RETURN labels(n) AS type, count(n) AS count ORDER BY count DESC;

-- All projects with HTML paths
MATCH (p:Project) RETURN p.name, p.uniqueId, p.htmlPath ORDER BY p.name;

-- Bridge entities (cross-project connections)
MATCH (e:Entity) WHERE e.projectCount > 1
RETURN e.name, e.projectCount ORDER BY e.projectCount DESC;

-- Entities in a project
MATCH (e:Entity)-[:MENTIONED_IN]->(p:Project {uniqueId: $uid})
RETURN e.name, e.category, e.definition;

-- Relationships in a project
MATCH (a)-[r:RELATES_TO]->(b),
      (a)-[:MENTIONED_IN]->(p:Project {uniqueId: $uid})
RETURN a.name, r.relType, b.name, r.description;

-- Causal chains for a project
MATCH (cc:CausalChain {projectId: $pid})
RETURN cc.name, cc.description, cc.linkCount;

-- Fulltext search
CALL db.index.fulltext.queryNodes("entity_fulltext", "monetary policy")
YIELD node, score RETURN node.name, score ORDER BY score DESC;

-- Embedding coverage
MATCH (e:Entity)
RETURN count(e) AS total,
  sum(CASE WHEN e.embedding IS NOT NULL THEN 1 ELSE 0 END) AS withEmbedding;
```

## Project Deletion (delete_project.py)

Full cascade deletion — removes Neo4j data and filesystem artifacts.

```bash
python neo4j/delete_project.py <unique-id>              # Delete project
python neo4j/delete_project.py <unique-id> --dry-run    # Preview only
python neo4j/delete_project.py <unique-id> --keep-files # Neo4j only
```

Cascade: CausalChains → TemporalEvents → Relationships → Entities (decrement/delete) → Project → Filesystem (sources + extracted + projects).

Always run `python neo4j/gds.py` after deletion to recompute metrics.

## Collection Export (export_collection.py)

Exports a complete collection as a portable knowledge graph package. Everything an agent or human needs — no Neo4j required.

```bash
python neo4j/export_collection.py --list                          # List collections
python neo4j/export_collection.py "Global Finance Systems"        # Full ZIP export
python neo4j/export_collection.py "Global Finance Systems" --json-only    # graph.json only
python neo4j/export_collection.py "Global Finance Systems" --no-embeddings # Skip raw vectors
```

### Export Package Contents

```
<collection-slug>.zip
├── graph.json          ← Complete knowledge graph (agent-readable, no DB needed)
├── embeddings.json     ← Raw 384d BERT vectors (for vector search apps)
├── manifest.json       ← Export metadata, checksums, schema version
├── README.md           ← Human-readable collection overview
└── projects/<slug>/
    ├── source.html     ← Full styled source document
    └── extraction.json ← Raw extraction artifacts
```

### graph.json Structure

Contains everything an agent needs to reason over the collection:

| Section | What | Count (example) |
|---------|------|-----------------|
| `meta` | Collection name, stats, export date, schema version | — |
| `projects` | Summaries, narrative flows, tags, temporal phases | 7 |
| `entities` | Definitions, roles, aliases, GDS metrics, bridge tiers | 287 |
| `relationships` | Source→target with evidence, classification, magnitude | 217 |
| `causal_chains` | Named chains with ordered mechanistic links | 24 (117 links) |
| `bridges` | Pre-computed cross-project entities (gold/silver/bronze) | 41 |
| `similar_pairs` | Pre-computed embedding similarity pairs | 227 |

### How It Works

1. Finds collection in Neo4j by name
2. Pulls all data in 8 batch Cypher queries (projects, entities, relationships, chains, temporal events, similarity, embeddings)
3. Locates source files on disk via htmlPath stored in Neo4j
4. Enriches causal chain links from extraction JSON files (Neo4j stores chain metadata, links live in extraction files)
5. Deduplicates entities, computes bridge tiers, assembles graph.json
6. Packages everything into ZIP with manifest and checksums

## Collection Import (import_collection.py)

Imports a portable collection export (ZIP) into a MemoryTonic Neo4j instance. Reconstructs per-project artifacts from graph.json, then reuses upload.py for database operations.

```bash
python neo4j/import_collection.py <path-to-zip> --dry-run                     # Validate first (ALWAYS)
python neo4j/import_collection.py <path-to-zip> --directory Research           # Import to Research directory
python neo4j/import_collection.py <path-to-zip> --collection "Custom Name"     # Override collection name
python neo4j/import_collection.py <path-to-zip> --force                        # Skip conflict prompts
```

### Import Pipeline (6 Phases)

1. **Pre-flight:** Verify Neo4j + schema, extract ZIP, read manifest + graph.json + embeddings
2. **Conflict detection:** Check existing collection/projects, list directories, report entity overlap
3. **Artifact reconstruction:** Build per-project upload folders from graph.json (5 of 6 artifacts — skips NLP)
4. **Validate + Upload:** `validate_project.py --import-mode` then `upload.py` for each project
5. **GDS Recompute:** PageRank, Betweenness, Degree, Similarity on full graph
6. **Verify:** Compare expected vs actual counts, report bridges

### Key Details

- **Cross-project entity resolution:** Extraction files may reference entities from other projects (bridges). The importer scans relationships/chains, resolves by name and alias, creates stubs for unresolvable names.
- **Pre-computed metrics discarded:** GDS metrics from the export are recomputed fresh because they depend on the full graph state.
- **Existing projects skipped:** If a project name already exists, it's skipped (not overwritten). Use `delete_project.py` first to reimport.
- **`--import-mode` validation:** Skips the `03_nlp_entities.json` check (NLP output not available in exports).
